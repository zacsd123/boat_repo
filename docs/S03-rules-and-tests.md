# S03. 규칙 모듈과 자동 시험

- **묶음**: 준비
- **앞 단계**: S02
- **크기(어림)**: 큼
- **끝나면**: 규칙의 판정이 화면과 떨어진 모듈(`Shared/Rules`)에 있고, 시험 54개와 기획 문서의 예시 플레이 두 판이 서버를 켤 때마다 통과한다.

규칙을 지키게 하는 가장 값싼 장치다. 판정을 파트나 캐릭터와 떼어 두면 캐릭터를 움직여 보지 않고도 "무게가 한계와 같으면 버틴다" 같은 규칙을 확인할 수 있다. 뒤 단계에서 무엇을 고치든 서버를 켤 때마다 다시 확인된다. 뒤 단계의 서비스는 여기서 만든 함수를 부르기만 한다.

| BL-3 | 한 번 울리기 시작한 종은 멈추지 않는다. 상자가 버려져 물이 띠 아래로 내려가도 그대로 간다. |
| BL-4 | 셋째 종이 울리는 순간 출항이다. 그보다 늦게 도착한 놓기는 없던 일이 된다. |

| SC-2 | 침몰하면 가라앉힌 사람은 그 배 0점이다. 나머지는 침몰 순간 갑판에 놓여 있던 자기 상자 점수를 전부 받는다. |
| SC-3 | 가라앉힌 사람이 잃는 것은 그 배의 점수뿐이다. 쌓아 둔 총점은 건드리지 않는다. |

| SC-6 | 이번 배 1등은 다음 배 동안 선장 모자를 쓴다(동점이면 모두). 그 배에서 점수를 낸 사람이 없으면 선장 모자는 없다. 표시일 뿐 효과는 없다. |
| SC-7 | 총점 1등은 왕관을 쓴다(동점이면 모두). 표시일 뿐 효과는 없다. |

| CR-8 | 갑판의 내 상자는 꾹 눌러 다시 들 수 있다. 드는 순간 무게와 점수에서 빠지고, 다시 놓으면 새로 싣는 것으로 판정한다. 들고 갑판 밖에 놓으면 버린 것이 된다. |

| IN-2 | 손에 상자가 있으면 톡 누르기는 놓기다. |

| IN-4 | 빈손으로 갑판에 있으면 톡 누르기는 되찾기다. 끌어안긴 내 상자가 손 닿는 거리에 없으면 아무 일도 일어나지 않고, 앞에 있는 상자에 고리가 잠깐 비쳐 꾹 눌러야 한다는 것을 알려 준다. |
| IN-5 | 빈손으로 갑판의 상자 앞에서 0.5초 꾹 누르면 남의 상자는 끌어안기, 내 상자는 다시 들기다. |

| HG-3 | 꾹 누르기가 끝나면 끌어안기가 시작된다. 그때부터 3초 동안은 취소도 다른 행동도 못 한다. |
| HG-4 | 끌어안긴 상자는 3초가 찰 때까지 갑판에 있는 것으로 친다. 무게와 주인 점수에 그대로 들어간다. |

| HG-7 | 라운드가 끝나면(출항 또는 침몰) 진행 중이던 끌어안기는 무효다. 그 상자는 주인 점수로 정산된다. |

| JN-1 | 도중 참가자의 총점은 그 순간 참가자(봇 포함) 중 가장 낮은 총점이다. 첫 배 도중이면 0이다. |
| JN-3 | 나간 사람이 끌어안던 상자는 제자리에 남는다. |

| VR-1 | 배는 작은 배, 보통 배, 큰 배가 있다. 한계 범위는 보통 배의 값에서 양 끝을 한 사람당 큰 상자 하나(4)만큼 내리거나 올린다. 띠의 폭은 같다. |
| GP-4 | 화물칸의 칸이 다 차면 가장 가까운 칸의 2층에 쌓는다. 2층이 있는 칸에서는 위 상자가 먼저 대상이 된다. |

| GP-7 | 끌어안긴 상자는 주인도 다시 들 수 없다. 주인이 할 수 있는 것은 되찾기다. |
| GP-9 | 꾹 누르기 시간은 클라이언트가 재고, 서버는 누르기 시작과 끝 사이가 정해진 시간보다 0.1초 넘게 짧지 않은지 확인한다. |
| GP-12 | P가 4보다 작을 때는 한계 범위 표의 1\~3명 값을 쓴다. 그런 때는 둘이다. 봇을 만들기 전에 적은 인원으로 시험할 때, 그리고 가만히 있는 사람을 P에서 뺀 라운드. 띠의 폭은 4명과 같게 두고 아래 끝을 세 번째 왕복의 첫 상자에 맞춘다. 3명은 28\~56이다. 4명의 값을 인원에 비례시킨 30\~51로는 종이 울린 뒤 하나 더 실을 이유가 없어진다. |
| GP-16 | 총점이 모두 0인 동안에는 왕관이 없다. 선장 모자가 점수를 낸 사람이 없으면 없는 것과 같은 원리다. |
| GP-19 | 끌어안긴 내 상자가 손 닿는 거리에 있는 동안에는 버튼을 누르는 순간 되찾기가 된다. 꾹 누르기로 넘어가지 않는다. 급하게 길게 누르다가 다른 상자를 들거나 끌어안는 실수를 막으려는 것이다. |
| GP-20 | 판 도중에 나갔다가 같은 판에 다시 들어온 사람은 나가기 전의 총점과 그 순간 꼴찌의 총점 가운데 낮은 쪽에서 시작한다. 꼴찌가 나갔다 들어와 한 등 위의 점수를 받는 길을 막으려는 것이다. |

## 만들 것

1. **`Shared/Rules` 아래에 모듈 여섯.** 어느 것도 Workspace, Players, 파트, 캐릭터를 만지지 않는다. 받은 값으로 계산해 결과만 돌려준다. 숫자는 직접 적지 않고 부르는 쪽이 Config에서 읽어 넘긴다.

   | 모듈 | 함수 | 하는 일 |
   | --- | --- | --- |
   | `BoatRules` | 새 배(아래 끝, 위 끝, 한계) | 무게 0, 젖은 자국 0, 띠에 닿은 적 없음, 끝나지 않음 |
   | | 놓였다(배, 갑판 무게의 합) | 끝난 배면 "없던 일". 아니면 무게와 젖은 자국을 고친다. 처음으로 아래 끝 이상이 됐으면 "띠에 닿음"을, 한계보다 크면 "침몰"을 돌려준다. 둘은 함께 나올 수 있다 |
   | | 빠졌다(배, 갑판 무게의 합) | 무게만 고친다. 젖은 자국은 그대로이고 판정은 하지 않는다 |
   | | 떠났다(배) | 끝난 배로 표시한다 |
   | `BellRules` | 간격 뽑기(아래 끝, 위 끝, 난수 함수) | 두 값을 따로 뽑는다. 소수까지 고르게 |
   | | 새 종(상한, 간격 1, 간격 2) | 울린 종 0 |
   | | 첫 종(종, 지난 시간) | 아직 안 울렸으면 울리고 둘째 종과 셋째 종의 시각을 정한다. 이미 울렸으면 아무 일도 없다 |
   | | 시간이 흘렀다(종, 지난 시간) | 상한이 지났는데 첫 종이 없으면 울린다. 시각이 된 둘째 종과 셋째 종을 울린다. 이번에 울린 종의 번호를 돌려준다. 3이 있으면 출항이다 |
   | `ScoreRules` | 배 점수(참가자들, 갑판의 상자들, 가라앉힌 참가자) | 참가자별 합. 가라앉힌 참가자는 0 |
   | | 총점에 더하기(총점, 배 점수, 배율) | 배 점수에 배율을 곱해 더한다. 이미 쌓인 총점은 줄지 않는다 |
   | | 앞선 사람들(점수) | 가장 높은 점수의 참가자들. 가장 높은 점수가 0이면 아무도 없다. 선장 모자와 왕관에 쓴다 |
   | | 순위(총점, 마지막 배 점수) | 총점 순. 같으면 마지막 배 점수가 높은 쪽. 그래도 같으면 공동 순위 |
   | `InputRules` | 톡 누르기(상황) | 놓기, 버리기, 황금 내려놓기, 들기, 되찾기, 힌트, 없음 가운데 하나 |
   | | 꾹 누르기(상황, 대상, 누른 시간) | 끌어안기, 다시 들기, 없음 가운데 하나 |
   | | 누르는 순간(상황, 대상) | 꾹 누르기를 시작할지, 바로 톡 누르기로 보낼지 |
   | | 되찾을 수 있나(주인의 상태, 갑판 위인지, 상자까지의 거리, 지금 시각, 다음 가능 시각) | 참 또는 거짓 |
   | `JoinRules` | P 세기(참가자들) | 봇, 지난 라운드에 입력이 있던 사람, 방금 들어온 사람을 센다. 0이면 1 |
   | | 봇 수(사람 수) | 채우는 인원에서 사람 수를 뺀 값. 0보다 작으면 0 |
   | | 시작 총점(총점들, 나가기 전 총점) | 가장 낮은 총점. 같은 판에 다시 들어온 사람은 나가기 전 총점과 견줘 낮은 쪽 |
   | `HugRules` | 끝의 결과(이유) | 끌어안기가 끝나는 여섯 가지 길마다 상자와 끌어안던 사람이 어떻게 되는지 |

   "상황"은 서버가 그 순간에 본 것을 묶은 값이다: 라운드 단계, 참가자 상태, 갑판 구역 안인지, 든 상자의 종류, 들 것이 손 닿는 곳에 있는지, 되찾을 상자가 있는지. "대상"은 누르려는 실린 상자다: 내 것인지, 누가 끌어안고 있는지, 위에 다른 상자가 있는지.

2. **시험.** `Server/Tests`에 아래 표를 그대로 옮긴다. 기대와 다르면 어느 번호인지 찍고 오류로 멈춘다. 시험 이름에 규칙 번호를 달아 둔다. 규칙이 바뀌면 어느 시험을 고칠지 바로 찾을 수 있다.
3. **언제 돌리나.** Studio에서 서버가 켜질 때마다 돌린다(`DEBUG_RUN_TESTS`). 게시한 서버에서는 돌리지 않는다.
4. **클라이언트도 같은 모듈을 쓴다.** 버튼의 그림(S07, S17, S19)은 클라이언트가 `InputRules`에 같은 상황을 넣어 얻는다. 그래서 `Shared`에 둔다. 숨은 한계는 모듈이 아니라 서버가 만든 "배" 값 안에 있고, 그 값은 서버 밖으로 나가지 않는다.

## 하지 않는 것

## 주의할 곳

- "놓였다"는 침몰이어도 "띠에 닿음"을 함께 알린다(T05). 물을 띠에 닿게 한 바로 그 상자가 배를 가라앉힐 수 있고, 그때는 첫 종과 침몰이 같은 순간이다.
- "빠졌다"는 침몰도 첫 종도 판정하지 않는다. 판정은 놓일 때만 한다(BT-6).
- 종은 무게를 모른다. 그래서 무게가 줄어도 종이 멈추지 않는다는 것(BL-3)이 구조로 지켜진다. `BellRules`에 무게를 넘기고 싶어지면 넘기지 않는다.
- 간격은 라운드가 시작될 때 뽑아 "새 종"에 넣어 둔다. 첫 종이 울릴 때 뽑는 것과 결과는 같고, 난수가 한 곳에 모인다.
- 규칙을 바꿀 때의 순서는 기준서(`01-rules.md`), 이 시험, 코드다. 시험을 나중에 고치면 틀린 코드가 통과한 채로 남는다.
- 이 시험은 판정만 지킨다. "서버가 판정 함수를 제대로 부르는가"는 뒤 단계의 완료 확인이 본다. 둘 다 있어야 한다.
