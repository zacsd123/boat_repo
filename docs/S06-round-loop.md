# S06. 라운드 단계의 뼈대

- **묶음**: 1묶음 · 사람끼리 하는 배 한 척
- **앞 단계**: S05
- **크기(어림)**: 보통
- **끝나면**: 서버가 "배 도착, 싣기, 종 세 번, 출항, 정산"을 시간만으로 끝없이 되풀이하고, 모든 클라이언트가 같은 단계를 본다.

## 지킬 규칙

<!--RULES: FL-4 FL-5 FL-6 FL-9 BL-2 GP-6-->

| 번호 | 규칙 |
| --- | --- |
| FL-4 | 라운드 시작: 뱃고동이 울리고 상자 더미가 열린다. 각자 있던 자리에서 시작한다. 더미는 라운드 동안에만 열려 있다. |
| FL-5 | 라운드는 셋째 종의 출항이나 침몰로 끝난다. 보통 26\~34초이고 가장 길어도 54초다. |
| FL-6 | 정산(12초): 출항 또는 침몰 연출 3초, 각자의 상자가 점수로 바뀌는 5초, 다음 배가 들어오는 4초. 그동안 모두 자유롭게 움직인다. |
| FL-9 | 최종 결과가 끝나면 총점이 0으로 돌아가고 판 시작부터 다시 한다. 사람이 한 명이라도 있으면 서버는 판을 쉬지 않고 이어 돌린다. |
| BL-2 | 둘째 종은 첫 종 3\~7초 뒤, 셋째 종은 둘째 종 3\~7초 뒤다. 두 간격은 라운드마다 따로 고르게 무작위로 뽑는다. 남은 시간은 어디에도 표시하지 않는다. |
| GP-6 | 출항하면 갑판 위에 있던 사람은 선착장에 내려 준다. 물에 빠뜨리지 않는다. 끝까지 지키던 사람이 다음 배에서 손해 보지 않게 하려는 것이다. |

이 단계에는 상자도 무게도 없다. 그래서 첫 종은 임시로 상한 시각에 울린다. "물이 띠에 닿는 순간"은 S10에서, 침몰은 S09에서 붙는다.

## 쓰는 수치

| 키 | 값 | 뜻 |
| --- | --- | --- |
| `SETTLE_SHOW_TIME` | 3 | 정산 첫 부분: 출항 또는 침몰 연출(초) |
| `SETTLE_SCORE_TIME` | 5 | 정산 둘째 부분: 상자가 점수로 바뀜(초) |

| `DEBUG_FORCE_BELL_GAPS` | 없음 | 종 간격 둘을 정한 값으로 고정한다 |

## 만들 것

1. **`RoundService`의 단계 순환.** `Arriving → Loading → Departing → Scoring → Arriving`을 되풀이한다. 서버에 사람이 처음 들어온 순간 `Arriving`부터 시작한다.
2. **임시 종.** `Loading`에 들어갈 때 `BellRules`의 "간격 뽑기"로 간격 둘을 `BELL_GAP_MIN`과 `BELL_GAP_MAX` 사이에서 따로 뽑아 "새 종"을 만든다(S03). 정수가 아니라 소수까지 고르게 뽑힌다. 그 뒤로는 매 프레임 "시간이 흘렀다"를 부르는 것이 전부다. `FIRST_BELL_CAP`이 지나면 첫 종이 울리고, 뽑아 둔 간격대로 둘째 종과 셋째 종이 울린다. 셋째 종에 `Departing`으로 넘어간다.
3. **상태 알리기.** 배의 속성 `Phase`, `BoatIndex`, `BellCount`를 바꾼다. 뽑은 간격과 다음 종 시각은 `RoundService` 안의 지역 변수로만 둔다.
4. **시간 재기.** 단계가 시작된 서버 시각을 적어 두고, 매 프레임 "지금 시각이 시작 시각 + 길이를 넘었는가"를 본다. `task.wait(길이)`를 이어 붙이지 않는다. 그렇게 하면 오차가 쌓이고, 나중에 침몰로 단계를 끊기 어렵다.
5. **배의 드나듦.** `Arriving` 동안 배가 바다 쪽에서 선착장 옆자리로 들어온다. `Departing` 동안 나간다. `Scoring` 동안에는 배가 없다.
6. **출항 때 갑판 위 사람.** `Departing`에 들어가는 순간 갑판 구역 안의 캐릭터를 선착장 머리로 옮긴다(GP-6).
7. **뱃고동.** `Loading`에 들어가는 순간 `Fx`를 한 번 보낸다.
8. **개발용 표시.** 화면 구석에 단계 이름, 배 번호, 종 수를 글자로 띄운다. S14에서 지운다.
9. **DevTools: 종 간격 고정.** `DEBUG_FORCE_BELL_GAPS`가 있으면 뽑지 않고 그 값을 쓴다.

## 하지 않는 것

- 판(8척)과 총점은 만들지 않는다. S23까지는 배가 끝없이 온다.
- 클라이언트에 남은 시간을 보내지 않는다. 개발용 표시에도 종까지 남은 시간은 넣지 않는다.

## 완료 확인

- [ ] 클라이언트 4개에서 단계 글자가 같은 순간에 바뀐다.
- [ ] 종 간격을 3과 7로 고정하면 `Loading`이 50초(40 + 3 + 7)에 끝난다. 7과 7이면 54초다.
- [ ] `Departing` 3초, `Scoring` 5초, `Arriving` 4초로 정산이 12초(±0.2)다.
- [ ] 간격을 고정하지 않고 20번 돌리면 서버 출력에 찍힌 간격이 모두 3과 7 사이이고 매번 다르다. 두 간격이 서로 같은 값으로 붙어 다니지 않는다.
- [ ] 클라이언트의 탐색기와 원격 이벤트 어디에서도 간격이나 다음 종 시각을 찾을 수 없다.
- [ ] `Loading` 중에 갑판에 서 있다가 셋째 종이 울리면 선착장 머리에 서 있다. 물에 빠지지 않는다.
- [ ] 클라이언트를 전부 끄면 서버가 닫히고, 다시 들어오면 `Arriving`부터 시작한다.
- [ ] 10분 동안 돌려도 단계의 길이가 어긋나지 않는다(서버 출력에 찍힌 각 단계의 실제 길이).
- [ ] 서버를 켤 때 도는 규칙 시험(S03)이 전부 통과한다.

## 주의할 곳

- 종은 단계가 아니라 `Loading` 안의 숫자(`BellCount`)다. 종마다 단계를 만들면 S09의 침몰이 "어느 종 단계에서 끊겼나"를 따져야 해서 복잡해진다.
- 단계를 바꾸는 코드는 한 군데(`RoundService.setPhase`)로 모은다. 침몰, 셋째 종, 사람이 다 나감이 모두 이 함수를 지난다.
- 배가 들어오는 4초 동안 사람이 선착장 머리에 서 있어도 배에 밀려 떨어지지 않아야 한다. 배가 들어오는 길과 선착장이 겹치지 않게 한다.
