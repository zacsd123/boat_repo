### Script Sync에서 배운 것
- Beta Features에 Script Sync가 없다(이미 정식 기능). 한국어판 메뉴: `스크립트 동기화 ▶ 동기화 대상… / 동기화 중지 / 동기화 재개 / 디스크에서 보기`.
- "동기화 대상…"은 고른 폴더 **안에** 같은 이름 폴더를 만들어 잇는다. 세 폴더 모두 `src`를 고른다.
- 오류로 멈춘 뒤 "동기화 재개"를 누르면 Studio 쪽이 디스크를 덮을 수 있다(두 번 지워져 git으로 되살림). 재개 전에 양쪽을 같게 맞춘다.
- MCP로 만든 Script는 RunContext가 Legacy라 `.legacy.luau`가 됐다 → `Server`로 바꿈. 비활성화된 스크립트는 동기화되지 않는다.

## S08 무게와 수위, 빨간 띠, 젖은 자국

- 무게는 `Map.Boat.Cargo`의 상자 종류로 **처음부터 다시 더함**(BoatService.deckWeight).
- 빨간 띠와 젖은 자국: `Map.Boat.HullMarks`에 `RedBand`와 `WetMark`를 네 면씩(Root에 용접, Studio에 만듦). 띠는 선체 바깥 0.55(턱 0.5 바로 바깥), 젖은 자국은 0.6(띠 위에 보이게). 코드는 높이만 바꿈. 색은 임시.
- 띠의 위 끝 = 갑판 턱 꼭대기 = 빈 배일 때 수면 위 `HULL_FREEBOARD`. 빈 배의 Root 높이와 수면(`Sea.Surface` 윗면)으로 계산(숫자 없이).
- 젖은 자국은 빈 배의 물높이부터 최고 무게의 물높이까지(무게 0이면 숨김).
- 수위 막대: 화면 **오른쪽 위**(버튼과 안 겹치게) 세로 막대. 꼭대기 = 범위의 위 끝. 안전 구간, 빨간 구간, 물 채움 + 지금 수위 선 + 최고 수위 선. 임시 모양.
- 삐걱 소리: Roblox 기본 소리(`action_footsteps_plastic.mp3`)를 0.45배로 낮춰 반복(임시). 크기는 띠에 막 닿을 때 0.15 → 위 끝에서 1. Loading일 때만. 클라이언트가 Weight/RangeLo/RangeHi로 계산.
- 배 높이는 붙어 있을 때(Loading)만 무게를 따른다.
- DevTools `setWeight(목표)`, `removeOne()`. 시험용 상자는 주인 없음(OwnerSlot 속성 없음), 실제 놓기와 같은 판정을 지남.

잰 값: 4명 띠 2.47, 3명 3.00. 큰 상자 하나에 0.353씩. 무게 40에서 띠 아래 끝이 수면(0.00), 68에서 턱이 수면(0.00). 하나 지우면 배는 뜨고 젖은 자국은 남음. 삐걱: 39 안 남, 40 0.15, 60 0.76. 수위 막대 비율이 선체와 같음. 새 Loading에 무게 0, 자국 없음, 높이 원래대로.

받아들인 것: 갑판 위 캐릭터는 배가 크게 오르내릴 때(시험으로 한 번에 수십씩 바꿈) 갑판 위 높이가 2.85~3.70으로 잠깐 흔들린다. 실제 놓기 하나는 0.35만 움직인다.

## S09 숨은 한계와 침몰 판정

- 숨은 한계는 BoatService의 지역 변수(`round`) 안에만. `Random:NextInteger(lo, hi)`.
- 놓기 뒤 결과가 침몰이면 `RoundService.sink(놓은 사람)`: 가라앉힌 사람을 지역 변수에, 남은 종 버림, `Sinking`, `Fx("Sink", 슬롯)`, 서버 출력 "침몰. 가라앉힌 사람: 이름 (슬롯 n)".
- 침몰 연출: Sinking 동안 배가 `HULL_FREEBOARD` + 선체 높이만큼 내려감(배다리 뗌). 판정과 따로. 갑판 위 사람을 물에 빠뜨리는 것은 S12.
- 시험용 상자도 같은 판정. 가라앉히면 가라앉힌 사람은 없음.

확인 방법을 바꾼 것:
- "두 클라이언트 동시 놓기" → 클라이언트 하나로, 같은 서버 프레임에서 시험용 상자로 먼저 가라앉힌 직후 플레이어의 놓기를 처리 → 단계가 Sinking이라 버려지고 화물칸에 안 생김. **진짜 두 클라이언트로는 미확인.**
- "무게 40 미만은 20라운드 동안 안 가라앉음" → 같은 BoatRules로 1,000라운드(39까지 하나씩) 돌려 0번. 구조상(한계 ≥ 아래 끝) 그렇다.
- "클라이언트 3개로 한계가 28~56" → P를 3으로 고정하고 1,000번 뽑기로 확인(최소 28, 최대 56, 평균 42.34).

잰 값: 한계 47 고정에서 44+큰=48 침몰(슬롯 1), 43+큰=47 버팀, 든 채로는 무게 불변. 1,000번 뽑기(4명): 40~68, 평균 54.22, 40이 27번, 68이 30번, 모두 정수. 클라이언트의 속성 이름에 한계 없음.

## S10 종 세 번과 출항

- 종을 RoundService에서 **BellService**로 옮김(계획서대로). 간격 뽑기, 첫 종, 매 프레임 tick, 셋째 종의 출항 시각. RoundService는 돌려받은 출항 시각으로 Departing.
- 놓기 뒤 띠에 닿았으면 **침몰 처리보다 먼저** 첫 종.
- 종마다 `Fx("Bell", 번호)`, 셋째 종에 `Fx("Horn")`을 겹침. 소리는 임시(`electronicpingshort.wav`, `bass.wav` 0.5배).
- 돛대의 종: 클라이언트가 `BellCount`만큼 Bell1~3을 켬(노란 네온, 임시). 곧 울린다는 표시는 없음.
- `DevTools.bellSimulation(n)`: 실제와 같은 함수로 간격을 뽑아 첫 종부터 출항까지를 찍음.

잰 값: 36에서 종 없음, 40에서 첫 종. 간격 3·7 고정에서 첫 종 +3.01초 둘째, +7.00초 셋째와 출항(같은 프레임). 첫 종 뒤 무게를 39로 내려도 그대로. 셋째 종 직후 놓기는 상자를 안 만듦. 아무도 안 실으면 40초에 첫 종. 한계 41에서 38+큰=42는 첫 종과 침몰이 같은 순간, 그 뒤 종 없음. 시뮬레이션 100번: 6.68~13.40초, 평균 10.08, 7.5초 초과 96%. 10,000번: 평균 9.98, 92%(문서 93% 근처).

확인 방법을 바꾼 것: "4명이 큰 상자만 싣는 라운드 26~34초" → 계산. 넷이 동시에 시작하면 4.5, 12, 19.5초에 무게 16, 32, 48 → 첫 종 19.5초 + 간격 합 6~14초 = 25.5~33.5초. **실제 4명 판은 미확인**(S16에서도 본다).

## DevTools 쓰는 법

값 고정은 `src/Server/DevTools.luau` 맨 위의 지역 변수를 바꾸고 플레이를 다시 켠다(지금은 모두 없음/끔, 시험 돌리기만 켬). 명령은 플레이 중 서버 명령창에서:

```lua
local cmd = game.ServerStorage.DevCommand
cmd:Invoke("setWeight", 44)          -- 시험용 상자로 무게 맞추기
cmd:Invoke("removeOne")              -- 가장 나중 상자 지우기
cmd:Invoke("fakeTap", "Large")       -- 첫 플레이어 대신 Tap
cmd:Invoke("limitDistribution", 4)   -- 한계 1,000번 뽑기
cmd:Invoke("bellSimulation", 100)    -- 첫 종부터 출항까지 분포
cmd:Invoke("stopwatch", workspace.Map.Zones.PileLargeZone, workspace.Map.Zones.DeckZone)
```
