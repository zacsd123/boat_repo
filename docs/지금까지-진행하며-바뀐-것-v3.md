## S11-1 폰 화면 겹침과 출항 연출

- 이 단계의 문서(`S11-1-phone-and-departure.md`), `build.py`의 보충 단계 이름 처리, 코드(`Client/HudLayout`, 수위 막대 자리, 배다리 걷기, `GANGWAY_RETRACT_TIME`)는 **다른 작업에서 만들어 커밋하지 않은 채** 남아 있었다. 내용을 확인하고 Studio에서 완료 확인을 돌린 뒤 코드는 고치지 않고 커밋했다.
- 잰 값: 셋째 종 뒤 배다리가 10.00 → 0.5초 6.55 → 1.0초 1.66으로 짧아지고 약 1.5초에 사라진 뒤에야 배가 떠남. 선착장 쪽 끝은 움직이지 않음(0.000). Departing 3.00초, Loading(3·7) 50.00초 그대로. 셋째 종 순간 배다리 끝에서 선착장 쪽으로 걸은 사람은 떨어지지 않음. 다음 배는 배다리 10.00으로 다시 붙음. `GANGWAY_RETRACT_TIME=3`이면 Config 검사에서 멈춤.
- 폰 화면: 지금 창(750×381)에서 막대 24~187, 버튼 203~299로 안 겹침(같은 세로줄). 가로 높이 320~414인 폰은 계산으로 막대 124~218px, 버튼과 16px 띄움.
- "모두 나갔다가 다시 들어옴"은 Studio에서 혼자 나가면 서버가 닫혀 재현이 안 돼 코드로 확인(setPhase(nil) → 배다리 걷기 멈춤).

## S15 기록 장치

- `Telemetry`는 다른 서비스를 require하지 않고, 서비스들이 Telemetry를 부른다(순환 방지).
- 한 줄: `TELEMETRY,`로 시작하는 쉼표 30칸. 서버가 켜질 때 머리줄. 참가자마다는 한 칸에 `슬롯:점수:상자:가만히 선 초:물에 빠짐`을 `|`로. 2·3묶음용 8칸은 비움.
- 숨은 한계·종 간격은 `BoatService.roundLimit()`, `BellService.currentGaps()`로 서버 안에서만 넘김. 기록 줄(서버 출력)에는 한계가 있다(서버 로그는 주인만).
- "하나 더"는 상자를 **든 시각**이 첫 종 이후인 것(서버 지역 표에 적음).
- "가만히 선 시간": 첫 종 뒤 Loading, 빈손으로 한 자리(2스터드 안)에 1초 넘게 있으면 그 1초 + 이후 흐른 시간. 정의의 "1초"는 Telemetry의 `STILL_WINDOW`(재는 방법이라 Config가 아님).
- 주인 요약 창: 새 원격 이벤트 `Remotes/OwnerSummary`(Studio). `game.CreatorType == User`이고 `UserId == game.CreatorId`인 사람에게만 보낸다. 창은 받은 적이 있을 때만 생기고(개발용이라 글자 씀), 단계·배 번호·종 수와 요약을 보여 준다. 한계 없음. **그룹 소유로 옮기면 주인 판정을 다시 봐야 한다.**
- DevTools: `resetTelemetry`, `telemetrySummary`.

잰 값(3척): 배 1 출항, 라운드 30.25초, 상자 2, 하나 더(작은) 1, **가만히 5.48초**(5초 서 있음). 배 2는 **상자를 든 채 5초 → 0.00**. 배 3 침몰(무게 56, 한계 52). 요약: 3척 중 침몰 1(33%), 라운드 평균 15.14, 첫 종까지 8.46, 하나 더 0.33, 가만히 평균 1.83·최대 5.48, 상한 0 — 손으로 계산한 것과 같음. 줄의 칸 수 30 = 머리줄.

CrateService        Tap, 들기·놓기·버리기, 화물칸, 나간 사람 상자 치우기, dropCarried
