# 구조

단계 파일들이 같은 이름과 같은 틀을 쓰도록 한 번만 정해 두는 파일이다. 여기 적힌 것은 규칙이 아니라 만드는 방식이라, 더 나은 방식이 있으면 바꿔도 된다. 다만 "판정은 서버가 한다"와 "숨은 값은 클라이언트로 보내지 않는다" 둘은 규칙을 지키는 데 필요하므로 바꾸지 않는다.

## 원칙 여섯 가지

1. **판정은 서버가 한다.** 무게, 한계, 종, 점수, 끌어안기 시간, 거리 확인은 전부 서버에서 한다. 클라이언트는 "눌렀다"만 보내고, 결과는 서버가 바꾼 상태를 보고 그린다. 한 가지 단서가 있다. Roblox에서 캐릭터의 움직임은 그 사람의 클라이언트가 계산해 서버로 보낸다. 서버의 거리 확인은 그렇게 받은 위치를 쓰므로, 조작 도구로 빨리 걷는 사람은 걷는 시간 규칙을 어길 수 있다. 이것은 S31에서 "들고 온 시간"을 서버가 재는 것으로 막는다.
2. **숨은 값은 서버 밖으로 나가지 않는다.** 숨은 한계(BT-1), 뽑힌 종 간격과 다음 종 시각(BL-2)은 서버 스크립트의 지역 변수에만 둔다. 속성, 값 객체, 원격 이벤트의 인자, ReplicatedStorage 어디에도 두지 않는다. 클라이언트에 복제된 것은 조작하는 사람이 전부 읽을 수 있다.
3. **판정 함수 안에서는 기다리지 않는다.** 요청 하나를 받아 상태를 바꾸는 함수 안에서 `task.wait`, 트윈 완료 대기, 원격 호출 응답 대기를 하지 않는다. 그래야 요청이 서버에 도착한 순서대로 하나씩 처리된다(BT-7, BL-4, CR-10). 연출은 판정이 끝난 뒤 따로 돌린다.
4. **사람과 봇은 같은 길로 지난다.** 봇도 참가자 기록을 쓰고, 사람이 버튼을 눌렀을 때와 같은 서버 함수를 부른다. 봇용 판정을 따로 만들지 않는다.
5. **숫자는 Config의 키로만 쓴다.**
6. **규칙의 판정은 순수한 모듈에 두고 자동 시험을 붙인다.** `Shared/Rules`의 함수는 파트나 캐릭터를 만지지 않고, 받은 값으로 결과만 돌려준다. 서비스는 그 함수를 부르고 결과를 모형과 속성에 옮긴다. 시험은 S03의 표이고, Studio에서 서버를 켤 때마다 돈다.

## 원격 이벤트

클라이언트가 보내는 것은 셋뿐이다. 서버는 받은 값을 믿지 않고 자기 상태로 다시 확인한다.

| 이름 | 방향 | 인자 | 서버가 확인하는 것 |
| --- | --- | --- | --- |
| `Tap` | 클라이언트 → 서버 | 대상(더미 종류, 황금, 또는 없음) | 아래 "톡 누르기를 처리하는 순서" 전부 |
| `HoldBegin` | 클라이언트 → 서버 | 상자 번호 | 그 상자가 있는지. 시각을 적어 둔다 |
| `HoldEnd` | 클라이언트 → 서버 | 상자 번호, 다 채웠는지 | 시작과의 간격(GP-9), 단계, 상태, 거리, 주인 |
| `Fx` | 서버 → 클라이언트 | 연출 이름과 값 | 한 번 울리고 끝나는 것만 보낸다: 뱃고동, 종, 침몰, 출항, 풍덩, 끌어안기 경고, 꾹 누르기 힌트, 점수 날아감, 팡파르 |

- 같은 참가자의 요청이 `INPUT_MIN_INTERVAL` 안에 또 오면 버린다. 연타와 조작 도구를 함께 막는다.
- `Fx`에는 판정에 쓰이는 값을 싣지 않는다. 계속 이어지는 상태는 아래의 속성으로 알린다.

## 복제되는 상태

클라이언트는 이 속성들만 보고 화면을 그린다.

| 어디에 | 이름 | 뜻 |
| --- | --- | --- |
| `Workspace.Map.Boat` | `Phase` | 지금 단계 (아래 표) |
| | `BoatIndex` | 이번 판의 몇 번째 배인지 |
| | `BellCount` | 울린 종의 수 (0\~3) |
| | `Weight` | 지금 무게 |
| | `MarkWeight` | 이번 라운드의 최고 무게 (젖은 자국) |
| | `RangeLo`, `RangeHi` | 이번 라운드 한계 범위의 양 끝 (빨간 띠) |
| | `ShipSize` | 배 크기 (S28부터) |
| `ReplicatedStorage.Participants.<슬롯>` | `IsBot`, `UserId` | 봇인지, 사람이면 누구인지 |
| | `State` | 참가자 상태 (아래 표) |
| | `Carrying` | 손에 든 상자 종류 (없으면 빈 값) |
| | `BoatScore` | 이번 배에 실은 점수 |
| | `TotalScore` | 총점 (S23부터) |
| | `Hat`, `Crown` | 선장 모자, 왕관 |
| 실린 상자 모형 | `CrateId`, `Kind`, `OwnerSlot` | 번호, 종류, 주인 |
| | `HuggedBySlot`, `HugEndsAt` | 끌어안는 사람과 끝나는 시각 (S18부터) |
| | `Cell`, `Layer` | 화물칸의 칸과 층 |

**복제하지 않는 것**: 숨은 한계, 뽑힌 종 간격, 다음 종 시각, 입력이 있었는지 여부, 기록(Telemetry), 시험용 값.

시각은 서버 시계(`workspace:GetServerTimeNow()`) 기준으로 적는다. 클라이언트도 같은 시계를 읽을 수 있어서, 끌어안기 고리처럼 "언제 끝나는지"를 그릴 때 어긋나지 않는다.

## 라운드 단계

| 단계 | 길이 | 들어갈 때 일어나는 일 | 버튼 |
| --- | --- | --- | --- |
| `MatchIntro` | `MATCH_START_TIME` | 총점 0. 첫 배가 들어온다 (S23부터) | 꺼짐 |
| `Loading` | 종과 침몰이 정한다 | 뱃고동. 더미가 열린다. P를 세고 한계를 뽑는다 | 켜짐 |
| `Departing` | `SETTLE_SHOW_TIME` | 셋째 종. 점수를 굳힌다. 갑판 위 사람을 선착장에 내려 준다. 배다리가 `GANGWAY_RETRACT_TIME` 동안 걷히고, 다 걷히면 배가 떠난다(보여 주기일 뿐 단계는 이미 바뀌었다) | 꺼짐 |
| `Sinking` | `SETTLE_SHOW_TIME` | 한계를 넘김. 점수를 굳히고 가라앉힌 사람을 0으로. 갑판 위 사람은 물에 | 꺼짐 |
| `Scoring` | `SETTLE_SCORE_TIME` | 상자가 점수로 바뀌는 연출 | 꺼짐 |
| `Arriving` | `SETTLE_ARRIVE_TIME` | 다음 배가 들어온다 | 꺼짐 |
| `FinalShow`, `FinalLastScore`, `FinalPodium` | `FINAL_SHOW_TIME`, `FINAL_LAST_SCORE_TIME`, `FINAL_PODIUM_TIME` | 8번째 배 뒤의 최종 결과 (S23부터) | 꺼짐 |

- 종은 단계가 아니다. `Loading` 안에서 `BellCount`가 0에서 3으로 올라간다.
- 1묶음과 2묶음에서는 판이 없다. `Arriving → Loading → Departing 또는 Sinking → Scoring → Arriving`만 끝없이 돈다.
- 단계의 길이는 `task.wait`를 이어 붙여 재지 않는다. 단계가 시작된 서버 시각에 길이를 더한 값과 지금 시각을 견준다.

## 참가자 상태

| 상태 | 뜻 | 들어오는 길 | 나가는 길 | 할 수 없는 것 |
| --- | --- | --- | --- | --- |
| `Empty` | 빈손 | 놓기, 물에서 나옴, 끌어안기가 끝남 | 들기, 끌어안기 시작, 물에 빠짐 | — |
| `Carrying` | 상자를 들고 있음 | 들기, 다시 들기 | 놓기, 물에 빠짐, 라운드 끝 | 또 들기, 끌어안기, 되찾기 (CR-2, CR-7) |
| `Hugging` | 끌어안는 중 (3초) | 남의 상자를 꾹 누름 | 3초가 참, 되찾기를 당함, 라운드 끝, 주인이 나감 | 이동, 모든 버튼 (HG-3) |
| `InWater` | 물속 | 물 구역에 들어감, 침몰, 끌어안기가 참, 되찾기를 당함 | 사다리를 다 오름, 해변으로 나옴 | 모든 버튼 (WT-2) |

"갑판 위에 있다"와 "더미 앞에 있다"는 상태가 아니다. 요청을 받을 때마다 서버가 캐릭터의 위치로 그 자리에서 판단한다.

## 그 밖의 이름

`Shared/Types`에 모아 두고, 속성 값과 Config의 표에서 같은 낱말을 쓴다.

| 무엇 | 값 | 쓰이는 곳 |
| --- | --- | --- |
| 상자 종류 | `Small`, `Medium`, `Large`, `Gold` | 속성 `Kind`와 `Carrying`, Config의 `CRATE_SCORE`와 `CARRY_TIME` |
| 배 크기 | `Small`, `Normal`, `Large` | 속성 `ShipSize`, Config의 `FIRST_BELL_CAP`과 `SHIP_SIZE_MIX` |

## 톡 누르기를 처리하는 순서

`Tap`을 받으면 서버는 아래 순서로 본다. 규칙 IN-2, IN-3, IN-4가 이 순서에 들어 있으므로, 버튼의 뜻을 바꾸려면 여기를 고친다. 어느 갈래로 갈지는 `InputRules`의 "톡 누르기"가 정하고(S03), 서버와 클라이언트가 같은 함수를 쓴다. 아래는 그 함수의 답마다 서버가 하는 일까지 함께 적은 것이다.

```
Tap(참가자, 대상):
  1. 단계가 Loading이 아니면 버린다.                              (FL-4)
  2. 상태가 InWater나 Hugging이면 버린다.                         (WT-2, HG-3)
  3. 상태가 Carrying이면 놓기다.                                 (IN-2)
       갑판 구역 안:
         가장 가까운 빈 칸에 실린 상자를 만든다.                    (CR-5, GP-3)
         무게를 다시 더한다.                                     (BT-2)
         아직 종이 안 울렸고 무게가 범위의 아래 끝 이상이면 첫 종.    (BL-1)
         무게가 숨은 한계보다 크면 침몰. 가라앉힌 사람 = 이 참가자.  (BT-6)
       갑판 구역 밖:
         일반 상자는 사라진다. 황금 상자는 그 자리에 남는다.         (CR-6, GD-3)
  4. 상태가 Empty이고 갑판 구역 안이면 되찾기를 시도한다.           (IN-4)
       되찾을 것이 없으면 꾹 누르기 힌트만 보낸다.
  5. 상태가 Empty이고 갑판 구역 밖이면 들기다.                     (IN-3)
       대상 더미나 황금 상자가 TARGET_RANGE 안일 때만.
```

3번에서 첫 종 확인이 침몰 확인보다 먼저다. 같은 상자에서 첫 종과 침몰이 함께 날 수 있기 때문이다(BL-5).

셋째 종은 서버의 타이머가 단계를 `Departing`으로 바꾸는 것으로 처리한다. 그 뒤에 처리되는 `Tap`은 1번에서 버려지므로 BL-4가 따로 코드를 요구하지 않는다.

## 맵의 시작 배치

회색 블록으로 먼저 놓는 치수다(S04). 규칙이 요구하는 것은 스터드가 아니라 걷는 시간이므로, 초시계로 재서 어긋나면 거리를 고친다. 좌표는 X가 동서, Z가 남북(음수가 바다 쪽), Y가 높이이고 수면이 Y = 0이다.

```
              북 (바다)
        ┌────────────────────────┐   Z = -50
  사다리 │   통로                  │ 사다리
        │  ┌──────────────────┐  │
        │  │  화물칸 6 × 3칸    │  │   갑판 24 × 16
        │  └──────────────────┘  │
        │   통로        입구      │
        └───────────┬──┬─────────┘   Z = -34
   물 자리           │배│           물 자리
                    │다│
                    │리│               Z = -24
                  ┌─┴──┴─┐
                  │선착장 │  (머리, 높이 5)
                  │      │
                  │경사로 │  (높이 5에서 1로 내려옴)
   ~~~~~~~~~~~~~~~│~~~~~~│~~~~~~~~~~~   Z = 0 해안선
                  └──────┘               Z = 2
           작은  중간   큰  바위          (경사로 입구에서 같은 거리의 호 위)
                 스폰 자리
              남 (해변)
```

## 이 구조가 쓰는 Roblox 기능

이름을 알면 공식 문서에서 찾아볼 수 있도록 적는다. 2026년 10월에 확인한 것이고, 메뉴 이름은 바뀔 수 있다.
